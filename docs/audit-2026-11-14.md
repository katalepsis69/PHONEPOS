## Multi-store cloud layer, first look (new surface the v9 brief predates)

Shape: stores(store_id, store_name, pin_hash, created_at); shops.store_id references it;
the default store 'Main Store' is seeded at boot and adopts shops with no store; each store
has its own keypad PIN hashed with PBKDF2; manager sessions carry { storeId, storeName };
pairing codes minted by a manager pair the register into that manager's store.

Verified: store-scoped reads on /api/overview, /api/standing, /api/rows, /api/sale,
/api/analytics, /api/reorder, /api/inventory/reorder, /api/dead-stock (8 getStoreShopFilter
sites); ownership checks on DELETE /api/shops/:id, /api/inventory/adjust-stock,
/api/inventory/import (store shop whitelist before any write); /api/setup-pin stays
first-run-only (403 once a PIN exists, budgeted, refuses to overwrite);
/api/create-store budgeted, name-collision 409, adopts only NULL/unassigned shops (the
'default'-stealing bug named in its own comment is fixed); sessions are UUIDv4, HttpOnly,
SameSite=Strict, Secure behind TRUST_TLS_PROXY, 12h TTL with expiry eviction.

## 3. Future scale notes

- More than 8 stores: the nameless-login fallback's LIMIT 8 becomes a functional limit;
  the login form must then require the store name (one-line change when it matters).

  policy before a busy tenant starves another's mirror.

  supported path would remove a footgun when someone else runs releases.

  runs with debug verbosity.
