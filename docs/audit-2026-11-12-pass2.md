## 2. Findings

[MEDIUM] [CONFIRMED] src/sync.js:101-135 (applyCloudCommands) - unknown command kinds sit
pending forever.
What: the command loop acks adjust_stock and import_inventory (success or deterministic
refusal) and logs transient failures, but any OTHER kind falls through both branches with
no ack and no log. The cloud keeps serving it in every /sync response, every drain,
indefinitely, and nothing records why.
Trigger: version skew, exactly the case the command channel exists for: a newer cloud
mints a kind the workstation has not learned yet (or a corrupted kind string).
Impact: a permanently poisoned pending slot that also inflates the manager app's
"Unsynced - N queued" badge forever, with no diagnosis anywhere.
Fix sketch: an explicit else branch: ack the id and log "unsupported kind, acked" so a
version-skewed pair degrades to a log line instead of a silent queue.
(Note: first written as a remediation finding during the first pass's test-hardening pass;
this run's fix pass executes it.)

[LOW] [CONFIRMED] public/js/views/backoffice.js:990 - the Wholesale order tag misses the
wholesale tier.
What: the sales-history row renders the Wholesale tag only when customer_type is exactly
technician; the 2026-11-11 batch added wholesale as its own customer_type (src/sales.js:15)
and the counter now sends it (public/js/views/pos.js:1510).
Trigger: ring up any sale on the Wholesale tier button, open Sales history.
Impact: the tag exists to make wholesale orders visible at a glance; the tier it names is
the one it does not mark. Pricing is unaffected (the server treats technician and
wholesale identically).
Fix sketch: match both tier values.
