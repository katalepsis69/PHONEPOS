1. HIGH: POST /api/deploy turns a manager session into arbitrary persistent server code on the internet-facing VPS, with no audit row, no budget and no rollback copy (cloud-deploy/server.js:708).
2. HIGH: the license trial is defeated twice from the shop chair: a deleted seal reseeds honestly from attacker-edited rows (src/license.js:194), and a 23h59m daily clock crawl slips under the 24h rollback gate (src/license.js:208, :261).

## 3. Future Scale Notes

- Heartbeat times refetch fan-out: nine calls per phone per change per store; at ten shops and five phones this dominates the VPS. Shop-scoped refresh and a count guard fix the shape now.
- json_extract scans over shop_rows are O(table) per query per request; materialized typed tables become necessary around tens of thousands of mirrored rows per shop.
- PBKDF2-all-stores login amplification scales with tenant count; a global budget stops being optional before the second real tenant.
- The updater's cmd.exe handoff needs a real-machine exercise before any fleet-wide update campaign.
- publish/ at 3.1GB will outrun a backup disk; prune or exclude it from mirrors.
- Version control remains the single cheapest reliability upgrade available.
